# Поле рядом

Версия продукта: 16. Версия пакета: 0.5.3.

«Поле рядом» помогает фермерам размещать заказы на работы агродронов, а операторам — находить заказы, предлагать цену и передавать результат. Основной интерфейс работает как мини-приложение MAX; веб-версия доступна по адресу [vicosta-bot.ru](https://vicosta-bot.ru).

Ссылка на мини-приложение MAX имеет вид `https://max.ru/<имя_бота>?startapp`. Имя определяется настройками бота MAX или переменной `MAX_BOT_USERNAME`; фактическая ссылка не хранится в исходниках. Перед передачей проекта укажите действующую ссылку на бота и проверьте её в MAX.

## Основной сценарий

1. Открыть бота в MAX и отправить `/start`.
2. Открыть мини-приложение и выбрать роль фермера или оператора агродрона.
3. Фермер создаёт поле, выбирает культуру и задаёт границу на карте. Номер поля и площадь рассчитываются автоматически.
4. Фермер создаёт заказ на выбранное поле.
5. Оператор открывает заказ и отправляет предложение с ценой и будущими датой и временем.
6. Фермер выбирает предложение оператора; заказ переходит в статус «В работе».
7. Оператор загружает файлы результата и завершает заказ.
8. Фермер получает уведомление, открывает результат и просматривает или скачивает PDF-отчёт и материалы.

Для полного прогона нужны две учётные записи MAX: фермера и оператора.

## Состав и архитектура

- `src/` — интерфейс на React, страницы фермера, оператора и администратора.
- `backend/` — API на FastAPI, проверки доступа и бизнес-правил.
- `bot.mjs` — бот MAX и доставка уведомлений.
- `server.mjs` — локальная раздача собранного веб-интерфейса.
- `docker/` — настройка Nginx для интерфейса и запросов к API.
- `compose.yaml` и три `Dockerfile` — запуск интерфейса, API и бота.

Интерфейс обращается к API через `/api`. API хранит пользователей, роли, поля, геометрию, заказы, предложения, результаты, сессии и уведомления в SQLite. Загруженные файлы лежат отдельно от базы. В Docker база и файлы находятся в томе `agromax_data` и сохраняются при остановке и повторном запуске контейнеров.

## Внешние сервисы и данные

- MAX WebApp передаёт данные пользователя и подписанные `initData`; сервер проверяет подпись и срок действия. Бот использует MAX Bot API для сообщений и уведомлений.
- Яндекс.Карты отображают карту и позволяют задавать границы полей. Для полноценной работы карты нужен ключ Яндекс.Карт.
- Шрифт Manrope загружается из Google Fonts; при недоступности сервиса интерфейс использует системный шрифт.
- Подключённого источника агромониторинга, погоды или телеметрии дронов нет. Название поля, культура и контур вводятся пользователем; площадь вычисляется по контуру. Не представляйте эти данные как сведения из внешней агросистемы.

Файл `.env.example` содержит только пустые значения секретов. Рабочий `.env` не передавайте вместе с исходниками. Данные SQLite и загруженные файлы хранятся локально; резервное копирование в облако не настроено.

Для демонстрации создайте условное поле «Демо поле 1» с культурой «Пшеница», затем заказ «Облёт поля» с описанием «Демонстрационная проверка». Предложение оператора можно заполнить ценой 1500 и датой на следующий день. Используйте демонстрационный файл до 25 МБ; не загружайте реальные персональные или коммерческие материалы.

## Контракт API и демонстрационные учётные записи

`openapi.json` описывает методы и форматы API версии OpenAPI 3.1. `DATA-API.yaml` содержит базовые адреса, обязательные проверки, роли и ожидаемые статусы ответов. Файл `test-data.json` содержит синтетический пример поля, заказа, предложения и результата.

Для локального режима `NODE_ENV=development` доступны демонстрационные профили `preview-farmer` и `preview-operator`, без пароля. Они не работают в production. В production пользователь входит через MAX; тестирование требует двух действующих учётных записей MAX. Пароль администратора задаётся отдельно через `ADMIN_PASSWORD` и в проект не включён.

## Настройка и запуск через Docker

Скопируйте пример настроек и задайте собственные секреты:

```powershell
Copy-Item .env.example .env
```

В `.env` обязательно заполните `APP_SECRET` случайным секретом и `ADMIN_PASSWORD` уникальным паролем. Для карты добавьте ключ `VITE_YANDEX_MAPS_API_KEY`. Для запуска бота MAX укажите `MAX_BOT_TOKEN`, действующий публичный HTTPS-адрес приложения в `MAX_APP_URL` и при необходимости `MAX_BOT_USERNAME` или `MAX_BOT_ID`.

Собрать и запустить веб-интерфейс и API:

```powershell
docker compose up --build
```

Запустить также бота MAX:

```powershell
docker compose --profile max up --build
```

Для работы бота адрес из `MAX_APP_URL` должен открываться из интернета по HTTPS и вести к этому экземпляру приложения. Для локального прогона внутри MAX нужен публичный HTTPS-туннель или тестовый сервер; адрес `localhost` MAX открыть не сможет.

| Компонент | Адрес или порт |
| --- | --- |
| Веб-интерфейс | `http://localhost:8080` |
| Проверка API и базы | `http://localhost:8080/api/health` |
| FastAPI внутри Docker-сети | `8090`, напрямую на компьютере не опубликован |

При успешной проверке API ответ содержит `status: ok` и `database: connected`.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `APP_SECRET` | Секрет для подписи сессий, ссылок на файлы и административных токенов; обязателен |
| `ADMIN_PASSWORD` | Пароль административной панели; задаётся только в `.env` |
| `MAX_BOT_TOKEN` | Токен бота MAX; обязателен для профиля `max` и проверки MAX `initData` |
| `MAX_APP_URL` | Публичный HTTPS-адрес приложения, доступный из MAX |
| `MAX_BOT_ID` | Необязательный числовой идентификатор бота |
| `MAX_BOT_USERNAME` | Необязательное имя бота, используется для прямой ссылки |
| `VITE_YANDEX_MAPS_API_KEY` | Ключ Яндекс.Карт, передаётся при сборке интерфейса |
| `MAX_INIT_DATA_MAX_AGE` | Максимальный возраст подписанных данных MAX, по умолчанию 3600 секунд |
| `SESSION_MAX_AGE` | Срок жизни сессии пользователя, по умолчанию 2592000 секунд |
| `ADMIN_SESSION_MAX_AGE` | Срок жизни административного токена, по умолчанию 3600 секунд |
| `MAX_UPLOAD_BYTES` | Максимальный размер файла в байтах, по умолчанию 26214400 |
| `FILE_DOWNLOAD_TOKEN_TTL` | Срок жизни ссылки на скачивание в секундах, по умолчанию 900 |
| `NODE_ENV` | Режим сервера; для локального Compose по умолчанию `development` |
| `VITE_API_BASE_URL` | Адрес API при сборке интерфейса; для Compose используется `/api` |

## Пошаговая проверка

1. Запустите Compose и откройте веб-интерфейс. Убедитесь, что отображается экран выбора роли, а адрес `/api/health` возвращает успешный ответ с подключённой базой.
2. В MAX откройте мини-приложение под учётной записью фермера. Выберите роль, создайте поле «Демо поле 1» с культурой «Пшеница» и замкнутой границей. Ожидаемый результат: поле появляется в списке, номер присвоен, площадь больше нуля.
3. Создайте заказ по этому полю. Ожидаемый результат: заказ виден фермеру со статусом «В поиске» и оператору в списке доступных заказов.
4. Войдите под учётной записью оператора, отправьте предложение на 1500 с датой на следующий день. Ожидаемый результат: предложение появляется у фермера; дата в прошлом и некорректная цена отклоняются с понятной ошибкой.
5. Примите предложение от имени фермера. Ожидаемый результат: заказ переходит в статус «В работе», стороны получают уведомления в интерфейсе, а при работающем боте — и в MAX.
6. От имени оператора загрузите файл не больше 25 МБ и завершите заказ. Ожидаемый результат: статус становится «Готово», результат доступен фермеру.
7. Откройте результат от имени фермера, скачайте исходный файл и сформируйте PDF-отчёт. Ожидаемый результат: PDF открывается, а загруженные фотографии включены в отчёт.
8. Остановите и снова запустите Compose. Ожидаемый результат: приложение снова доступно, ранее созданные записи и файлы сохранены.

## Остановка и повторный запуск

Остановите контейнеры сочетанием `Ctrl+C` или командой:

```powershell
docker compose down
```

Запуск с сохранёнными данными:

```powershell
docker compose up -d
```

Для бота добавьте профиль `--profile max`. Команда `docker compose down -v` удаляет том с локальной базой и файлами; не используйте её, если эти данные нужны.

## Известные ограничения

- SQLite и локальный том подходят для демонстрации, но не для горизонтального масштабирования.
- Результаты агромониторинга, погода и управление дроном не подключены.
- Карта зависит от доступности Яндекс.Карт и действующего API-ключа.
- Для уведомлений и входа через MAX нужны зарегистрированный бот, действующий токен и доступный по HTTPS адрес мини-приложения.
- Максимальный размер одного загружаемого файла — 25 МБ.
- Действующая ссылка на MAX-бота должна быть указана отдельно перед сдачей: в исходниках хранится только механизм её получения из настроек бота.

## Административная панель

Маршрут `/admin` открывает отдельную консоль заказов, полей, результатов и пользователей. Доступ защищён паролем `ADMIN_PASSWORD`, который задаётся только в локальном или серверном `.env`.
